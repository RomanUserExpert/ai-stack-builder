# Ruler: what "one source, many agent targets" actually produces

Collected 2026-08-31 by running Ruler locally. This is the **substitute for Packmind**, whose
product is sales-gated: instead of a marketing screenshot we get the real per-target output.

`npx @intellectronica/ruler@latest apply` — version 0.3.44.

## Input

One source directory, two files:

```
.ruler/instructions.md     # the rules themselves, plain markdown
.ruler/ruler.toml          # default_agents = ["claude","cursor","copilot","codex","aider","gemini-cli"]
```

## Console output

```
[ruler] Applying rules for GitHub Copilot...
[ruler] Applying rules for Claude Code...
[ruler] Applying rules for OpenAI Codex CLI...
[ruler] Applying rules for Cursor...
[ruler] Applying rules for Aider...
[ruler] Applying rules for Gemini CLI...
[ruler] Updated .gitignore with 10 unique path(s) in the Ruler block.
Ruler apply completed successfully.
```

## What landed on disk

```
./AGENTS.md
./CLAUDE.md
./.aider.conf.yml
./.gemini/settings.json
./.gitignore          (modified, managed block)
```

## The finding: there are only two distribution strategies

**1. Copy the content, with provenance.** `CLAUDE.md` and `AGENTS.md` each carry the full rules
plus a source comment:

```markdown
<!-- Generated by Ruler -->

<!-- Source: .ruler/instructions.md -->

# House rules
- All documentation, code and UI copy in English.
...
```

**2. Point at a canonical file.** Aider and Gemini get a pointer, not a copy:

```yaml
# .aider.conf.yml
read:
  - AGENTS.md
```

```json
// .gemini/settings.json
{ "contextFileName": "AGENTS.md" }
```

**And a third thing nobody talks about: it manages `.gitignore`.** Generated files are fenced in a
named block so a re-run can find and replace them:

```
# START Ruler Generated Files
/.aider.conf.yml
/.aider.conf.yml.bak
/.codex/config.toml
/.mcp.json
/AGENTS.md
/CLAUDE.md
# END Ruler Generated Files
```

Note the `.bak` entries — it keeps a backup beside every file it overwrites.

## Observed, not explained

Despite the log line "Applying rules for GitHub Copilot" and "for Cursor", **no
`.github/copilot-instructions.md` and no `.cursor/rules/*.mdc` were written.** Both appear to have
been collapsed onto `AGENTS.md`, which Cursor and Copilot now read. We did not confirm the reason
from source; the observation is what matters — the number of genuinely distinct target formats is
smaller than the marketing of this whole category suggests.

## What this means for our export

- Our four targets are not four formats. They are at most **two mechanics — copy or point —** plus
  a naming and path convention per agent. That simplifies the Result screen enormously.
- Provenance comments in generated files are cheap and prevent the "who wrote this file" problem.
- Re-export needs a managed block or a backup, or it eats the user's edits. Ruler chose both.
- `.mcp.json` and `.codex/config.toml` appear in its ignore list, so it treats MCP config as a
  generated artifact too — same as our merged MCP config.
