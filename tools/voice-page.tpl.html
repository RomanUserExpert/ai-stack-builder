Phase 05 · Tone of voice and microcopy

How the product speaks, and every line it says

Phase 5 of 12 · all seven of the lesson’s steps · 1–5 Oct 2026 · source of truth: voice.md for the rules, microcopy.md for the lines, CLAUDE.md §14 for the summary

The screens of phase 04 already said real words, but those words were written together with the structure, and in places they named the same thing three ways. This phase gives AI Stack Builder one voice: five principles that are rules rather than adjectives, a dictionary with one word per concept, a forbidden list, and rules for each kind of element. Then every line on every screen was rewritten against them, and checked. A voice document that rewrote no screen is decoration.

START

How to read this

A voice is rules, not a mood. Every principle on this page carries the line of research it comes from, and a principle that could not was not kept.

This page is derived, not composed. The principles, the dictionary, the forbidden list, the rules by element and every was/now count below are read out of voice.md and microcopy.md when the page is built, so it cannot drift from them.

Two boundaries held throughout. Only text: no element was added, moved or removed in the rewrite, and a script compared every page’s markup with the last commit. The one exception is four fixes in step 07, approved by name. And your content is not ours: item and project names, descriptions, paths, env key names, repos and refs were never rewritten. The sentences that carry them were.

The audience decided the register before anything else did. The primary persona has copied the same files between projects for a year and suspects half of them do nothing. They want specifics, not an advertisement, and the whole category they choose from writes like a shop.

STEP 01

The inventory

Every line of the 80 wireframe pages in one table: screen, zone, line, type. Marked, not rewritten.

The inventory found no cheer at all: no exclamation marks, no emoji, no successfully, no oops. The wireframes had been written in the specification’s register from the start. What it found was inconsistency: twenty-three places where the screens said the same thing differently.

STEP 02

Principles

Five, each with a rule, a line written by it, a line that breaks it, and where it comes from. Three of them come from the competitors’ language: where the whole category writes the same way, the difference is the voice.

The competitors’ quiet copy was fetched for this step: taglines, buttons, trust labels, confirmations, sixteen quotes from eleven products, ten of them checked against the raw page. Registries talk about themselves (96,436 in the registry, Hand-picked, production-ready). Trust is a number or a badge (Verified, Quality Score). Risk sells the remedy (One in seven skills carries a critical security risk). Taglines aspire (Sprinkle a little magic on your day).

STEP 05

The sample

One screen first, read by the owner before anything else was touched. Run was chosen, because it carries nearly every register the specification had already fixed, and a wrong word costs most there.

The owner changed one decision on it. The dictionary had recommended Check for the control that opens the mode, since what happens first is a check. The owner’s answer was the main button in the project is Export. That puts Export on the Project screen, so it went to the register as Q36 before it went anywhere else. The control now reads Export…, the mode is titled Export, and the check inside keeps its own words: Checking, Checked, Check again.

{{SAMPLE}}
STEP 06

The roll-out

The other sixteen screens, one agent per screen, each given voice.md, the sample, and a shared table of the lines that recur across screens, so that sixteen writers would not drift.

The merge was computed, not transcribed. The rewrite changed no markup, so each page before and after aligns line for line, and the was/now table is built from the pages themselves. A cross-screen check then found three lines that two agents had written differently for one panel, and they were reconciled. The 239 prototype pages were rebuilt from the pages, and no old phrase survives in them.

{{ROLLOUT}}
STEP 07

The check

Every line checked against the dictionary and the table. The table of defects came first, was reviewed by the owner, and only then fixed, in the pages and the table together.

Screen against table: zero differences in either direction. No cliché, exclamation, emoji or successfully. Twenty-two defects all the same. Four of them needed markup, not text, and were approved by name: a stray link removed, the error code given its own line, and a shared project that reads as shared, which is register entry Q37.

What is open

The lesson is finished. What it could not settle is listed, not smoothed over.

OpenWhy it is not settled here
Can counts carry a verdict?0 problems · 0 notes still reads the same on an empty project and a perfect one. The voice made every count explicit, zeros included. It cannot make the channel wider.
Copying the link againQ37 made a shared project read as shared, and decided nothing about whether the owner can see or copy the link afterwards.
The receiver’s voiceEvery line addressed to the receiver states what their machine needs. None guesses how they feel, because nobody has asked them.
The longest rowThe wireframes were written at real length, but width is measured in phase 07, when there is a type scale to measure it with.

From here on, every new line is written against voice.md and recorded in microcopy.md. A line on a screen that is not in the table is a defect, and so is the reverse.
