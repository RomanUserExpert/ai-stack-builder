Design system / Patterns

Patterns

A pattern is a composition of components that already stands on three screens or more. Each one here was found on the screens, not designed for them: its signature is run over all 80 wireframe pages at every build, and the build fails if it stands on fewer than three. A screen counts once, and an overlay never counts. Every pattern is a file in design-system/patterns/ with no style of its own — the frames below are those files.

Pattern or components

Take a pattern when the screen does the job the pattern already does somewhere else: the same parts, in the same order, for the same reason. Then the screen inherits a layout that has been reviewed three times, and a person who has seen one of those screens already knows how this one works.

Take the components when the job differs even if the parts are the same — a place with one thing in it needs no search; a step that can be undone needs no confirmation. And when a composition is on one or two screens only: it is not a pattern yet. If it reaches a third, it is added here, with the three screens named.

Browse head

Made of: Page head · Search field · Filters button and popoverpatterns/browse-head.html

Stands on 3 screens: My library library-my-default, library-my-error-filtered, library-my-filters, library-my-link, library-my-loading, library-my-revoke; Public library library-public-default, library-public-error-filtered, library-public-filters, library-public-loading; Projects projects-default, projects-delete, projects-error-filtered, projects-filters, projects-loading. Also drawn under Item overlay, Import/export, which are overlays and not counted.

Take the pattern

The top of a place that holds a collection a person searches and narrows: the name and the one act, then a search and one Filters button, right above the list or the grid.

Take the components

A place that holds one thing — a project, a shared item — takes the Page head alone: there is nothing to search. A filter by kind is Tabs, under this head, not inside it.

Set with an item side panel

Made of: Row list · Set row states (§7) · Item side panel · Closepatterns/set-with-side-panel.html

Stands on 3 screens: Configuring project-configuring-item; Detached row project-detached-default, project-detached-error, project-detached-loading, project-detached-promote; Project project-item.

Take the pattern

A project's set with one item opened beside it: the rows stay where they are, the open one carries the pill, and the panel holds what can be done to that item — Detach, Reset, Promote.

Take the components

Editing the library original is the Item sheet over My library, not this. A list whose rows open nothing beside them is the Row list alone.

Configuring layout

Made of: Library panel · Scope switch · Tabs · Search field · Add to set · Page head · Row list · Remove from setpatterns/configuring-layout.html

Stands on 3 screens: Configuring project-configuring-default, project-configuring-empty, project-configuring-error-filtered, project-configuring-error-server, project-configuring-item, project-configuring-loading-add, project-configuring-loading, project-configuring-public; Detached row project-detached-default, project-detached-error, project-detached-loading, project-detached-promote; Project project-empty.

Take the pattern

The configuring mode: the library panel on the left reads and adds, the set on the right shows what is in it and removes. One fact in two places — membership shown in the panel, owned by the row.

Take the components

Viewing a project is the set alone, with no panel and no ✕: a row being read is not a row being changed (Q21). Keeping and editing items is My library, not the panel.

Run report

Made of: Run summary · Check stages · Finding box · File block · Export stage · Buttonpatterns/run-report.html

Stands on 4 screens: Run project run-default, run-error-check, run-error-export, run-error-setup, run-loading-export, run-loading, run-remove, run-success; Run single item run-item-default, run-item-loading, run-item-success; Run shared project run-shared-default, run-shared-loading, run-shared-success; Run shared item run-shared-item-default, run-shared-item-loading, run-shared-item-success.

Take the pattern

The Export mode's body, on every Run: the verdict line with its counts, the stages grouped as Findings and Handover, and the Export stage last — the irreversible step read after everything it depends on.

Take the components

A single finding outside Run is a Finding box on its own; a list of facts with no verdict is a Plain list. Never put Export beside the check as a button: it is the last stage (§8).

Confirmation

Made of: Dialog · Form actions · Buttonpatterns/confirmation.html

Stands on 4 screens: My library library-my-revoke; Project project-revoke, project-share; Projects projects-delete; Run project run-remove. Also drawn under Item overlay, Import/export, which are overlays and not counted.

Take the pattern

Before a step that cannot be walked back or that publishes: the veil, the sheet, a head that names the thing, the consequence in the present tense, then Cancel … the act — red only when it removes.

Take the components

An unclean export is confirmed inside the Export stage, not here. A step that can be undone needs no dialog at all.

Dialog with a field

Made of: Dialog · Text field · Form actions · Buttonpatterns/dialog-with-field.html

Stands on 3 screens: My library library-my-link; Detached row project-detached-promote; Project project-link.

Take the pattern

A dialog that asks for one value before it acts, or hands one over: the name of a promoted item, a link to copy. The field sits 16 px under the head, the act after it.

Take the components

More than a field or two is the Item sheet. A dialog that only names a consequence is a Confirmation.
