name: code-style
description: How TypeScript is written in my projects.
---
- Named exports only. No default exports.
- Imports: node built-ins, then packages, then local — one blank line between groups.
- Errors: throw typed errors from lib code; catch only at the edge.
- Names say what a thing is, not what type it is: `invoices`, not `invoiceArray`.

What it needs, and what it answers to

  • Requires nothing else
  • No env keys
  • Defers to the client’s ESLint config — where they disagree, that wins
